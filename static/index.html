EDI Failure Triage

One failed EDI transaction in. Out: which integration path the customer is on, which failure state it is in, two or three ranked causes with the evidence behind each, a customer reply, and the follow-up that prevents the next ticket.

Classification is code, not the model. The statuses are a finite table. The model only ranks, writes, and proposes.

On top of the engine sits a Claude Code skill written in the same structure Orderful uses for its own support skills: trigger prompts, required inputs, a numbered recipe, and behavior rules that propose before acting. A support engineer describes the stuck transaction in plain words, the skill gathers the inputs, calls the triage tool over MCP, checks the answer against a shared failure taxonomy, and hands back a reply and a follow-up. Same engine, four doors: this console, the CLI, the API, and Claude Code.
